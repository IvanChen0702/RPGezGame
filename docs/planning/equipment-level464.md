# 裝備 Lv 企劃欄位

`Equipment` 新增「等級」欄，1～100 整數；相容英文表頭 `Level`。只影響圖鑑、背包、裝備資訊的 Lv 顯示及等級排序，不參與能力計算、不新增穿戴限制，不寫入玩家裝備實例。

已確認 206 個模板的對照值位於 `tools/planning/equipment_levels464.json`，包含 205 件玩家裝備及 GM 武器。不是在遊戲中寫死的預設值，亦不隨企劃新增裝備自動重新評分。缺漏或無效值沿用舊來源推算；重新載入無等級的企劃時清除上一版模板評分，不偷偷保留舊值。

無銘胚刃的模板等級為 1；具有 `forge172` 的實例或 `forge172_` 自訂模板顯示「Lv.未評定」，不將模板的 1 分套到鍛造成品。

## 同步回企劃原表

目前提供的 Code.gs 會原樣讀取並發布 Equipment 的所有欄位，不需要更改原有發布函式。將 `tools/planning/equipment_levels464.gs` 加為同一 Apps Script 專案中的新檔案，執行 `applyEquipmentLevels464()`：

- 沿用原有 `ss_()` 的試算表選擇方式，按 ItemID 回填，不依列順序貼數值。
- 新增「等級」欄（已存在 Level 時沿用），檢查重複 ID、缺少的模板及已有不同評分；有衝突時於寫入前停止。
- 只寫等級欄及其驗證規則，不發布企劃、不改其他裝備欄位、不接觸玩家資料。
- 重跑相同值不會改動分數；未知的新模板不代填。

亦可使用 `tools/planning/equipment_levels464.tsv` 依 ItemID 手動回填。正式企劃已先套用時，不必為這次回填立即再次發布；先使用原本的 `verifyCurrentPublishedPlanning107()` 核對原表與正式內容。往後沿用「驗證企劃 → 發布企劃」流程。
